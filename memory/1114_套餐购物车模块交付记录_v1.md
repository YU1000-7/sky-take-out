## 已交付

- 套餐接口：新增、修改、删除、分页、详情、起停售，`/user/setmeal/list` 与 `/user/setmeal/dish/{id}`
- 购物车接口：添加、减少、列表、清空，菜品与套餐共用同一购物车并按口味合并数量
- 套餐与 `setmeal_dish` 同一事务整体写入 / 整体替换
- 起售与删除规则：起售要求套餐内菜品全部起售；删除拦截起售中、购物车引用、有效订单引用
- 加购写入名称、图片、单价快照，与 D 的订单提交口径一致（amount 为单价分，按 number * amount 计价）
- B 端套餐管理页：筛选分页、表单弹窗、选择菜品弹窗（复用 B 的菜品分页接口，接口不可用时可手动登记菜品）、图片上传、起停售、批量删除
- H5 首页容器：分类导航（依赖 B 的 `/user/category/list`，未交付时降级为全部套餐）、套餐区、菜品组件软接入点（全局注册 `DishList` 自动挂载）、购物车悬浮条
- H5 购物车页：加减、清空、合计、结算入口占位
- 单元测试与集成测试新增 25 项，`mvn test` 共 32 项全部通过
- 两个前端 `npm run build` 全部通过

## 关键设计决定

- 跨模块只读查询集中在 `GoodsQueryMapper`，避免与 B、D 的实体/Mapper 重名冲突；对方接口稳定后可原位替换。
- `setmeal_dish` 新增唯一键 `(setmeal_id, dish_id)`，`shopping_cart` 增加用户+商品查询索引；已有库需执行交付说明中的 ALTER 语句。
- 购物车空口味统一存 `null`，避免同一商品因空串差异拆成两条。
- 套餐新增时一律先落库为停售，再按起售规则校验后改为起售，防止绕过菜品状态校验。
