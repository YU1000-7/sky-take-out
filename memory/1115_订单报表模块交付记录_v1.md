## 关键设计决定

- `OrderStatusDTO` 用在 `PUT /admin/order/status` 统一流转入口，三个语义化接口复用同一套状态校验，
  避免 Day 1 冻结的 DTO 变成死代码。
- 下单前用 C 的 `GoodsQueryMapper` 再校验一次商品状态，防止加购后被停售的商品卖出。
- 订单号用 `yyyyMMdd` + 6 位随机序号并先查重，规避 `uk_orders_number` 冲突。
- 报表聚合放在应用层，MySQL 与 H2 行为一致，集成测试可以覆盖；后续可下推到 SQL，接口不变。
- 新增 `JacksonConfig`：`LocalDateTime` 统一序列化为 `yyyy-MM-dd HH:mm:ss`，
  否则接口会输出 `2026-11-04T12:00:00`，与 `docs/api.md` 不一致。
- 集成时修复了 C 分支引入的两处回归：H5 的 `/login`、`/address` 被改回占位页并丢了登录守卫；
  后台登录后默认页从 `/employee` 改为仪表盘 `/dashboard`。
